# 实现审查与验证（2026-09-23）

基线：`signoz-config/master` 的 `7a0b6a336de5267d8c829ac8b2c5f8fbed03a229`。当前线上 SigNoz 保存的原始 Compose 与该基线文件字节一致；本变更新增独立 `audit/` 服务，原有 Compose/collector/Fluent Bit 文件没有差异。目标版本调查为 Coolify 4.3.23、SigNoz v0.97.1、JobScheduler master f3d80d9f。

## R1 — 正确性、操作契约和边界

检查 `events.py`、`store.py`、`worker.py`、archive 批次格式，以及对应来源/状态测试。

发现并修复：未知操作者应为 null；HTTP 请求完成不能伪装为部署/业务成功；Laravel 日志可能有尾部空 extra；SigNoz 缺 method 时不能将查看误标为修改；超长行在 EOF 后续写不能把其尾部当新操作；轮转/重启游标要和事件同事务，多个文件不能被忙文件饿死。

验证：三平台格式、秘密字段丢弃、匿名操作、UI 模糊动作、partial line、重启/rename rotation、观察到截断后的状态重置、超长行、全局读取预算/轮询公平性通过。`copytruncate` 快速回长、来源被提前删除仍是明确边界，未承诺无条件零丢失。

## R2 — 防删、数据、故障恢复和权限

检查 `archive.py`、队列过期逻辑、IAM/lifecycle 模板、可选索引/代码关联、来源只读和凭证隔离。

发现并修复：上传恢复不能重新开启 30 天期限，批次现按原接收时间且最多跨一分钟；上传重试期间不能删掉批次中的部分行改变内容；压缩库差异不能导致重试哈希冲突，校验改为规范 JSON 内容；本机时钟明显漂移不能把不可缩短的锁写到很久以后；MinIO 的“无 legal hold”返回需与权限错误区分；超长辅助字段/深嵌套 JSON 不得堵死队列。

保护：版本化和默认 COMPLIANCE 30 日不满足则不确认归档；条件写、内容哈希、版本和锁校验后才出队；writer 无删除权限，cleaner 无写日志/缩短锁权限；法律保留和延长的锁优先；原生账号、机器凭证与 PR 作者不混同；可选索引默认关闭，启用须先核实目的 TTL。

真实本机验证：提前删除被存储拒绝、缩短保留被拒绝；相同批次重复发送和更换 gzip 压缩级别不新增版本；合成过期版本可清理，保留期内/外部 prefix 不受影响；S3 断连后本地事件/游标仍在，恢复后只归档一次；索引 503 不影响锁定归档。到期测试使用短期合成锁与旧元数据，不是等待 30 个真实日历日。

## R3 — 最终差异、包、集成与使用方式

检查全部新增文件、配置/secret 范围、独立 Compose、依赖锁、CI、CLI 查询和交付边界。

发现并修复：Compose tmpfs 带逗号的参数需整体引用；状态目录权限不安全时不能自动放宽；来源不可读在单次检查中返回失败；错误的可选索引配置只禁用副本，核心归档继续。清理分页持久化，损坏游标安全重置；查询包括保留版本，delete marker 不会静默隐藏已锁证据。

验证：本地完整套件 **37 passed**，其中 5 个场景实际访问专用 loopback MinIO Object Lock；formatter、限定 lint、Python 编译、pip 依赖检查、wheel 构建和 TOML/JSON/Compose 结构检查通过。没有新增 Web UI，因此 UI 改造不适用；CLI 原生日志→持久队列→S3→export 的真实进程链已验证，原平台没有写入/重启/部署测试。

本机未安装 Docker；PR 的 `Platform audit checks` 会在 Linux 临时 MinIO 上重跑完整套件并构建镜像、校验 Compose。以 PR 当前 head 的 checks 为远端结果来源，不把本机结构检查说成容器已运行。

本轮为独立审查的三个角度，测试重跑未单独计作审查轮次。当前无未修复的严重代码发现；已记录的故障路径修复均由相应断言验证。送入实际部署环境后仍需最终集成复审，最多六轮，不因本地通过跳过生产审核。
